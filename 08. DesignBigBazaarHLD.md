# Design Big Bazaar

---

# 1. Functional Requirements

## User Registration and Authentication

Users must be able to:

- Register using their phone number or email address.
- Log in securely.
- Manage their profile.
- Manage saved addresses.
- View their purchase history.
- Maintain secure login sessions.

Authentication can support OTP and password-based login, with MFA for additional security.

---

## Product Catalog

The platform should provide a complete product catalog containing categories such as:

- Groceries
- Electronics
- Fashion
- Home appliances
- Personal care
- Household products
- Food and beverages

Each product should contain:

- Product name
- Description
- Images
- Category
- Price
- Discount
- Availability
- Inventory information
- Seller/store information
- Product ratings

Users should be able to browse products by category and search for products by name or description.

---

## Cart Management

Users should be able to:

- Add products to the cart.
- Remove products.
- Increase or decrease quantities.
- View cart contents.
- View item prices.
- View discounts.
- View the final cart amount.

The cart should remain available across sessions for authenticated users.

---

## Order Placement

Users should be able to:

1. Review their cart.
2. Select a shipping address.
3. Select a delivery method.
4. Apply promotions.
5. Select a payment method.
6. Confirm the order.
7. Receive an order ID.
8. Track the order.

---

## Payment Integration

Support secure payment methods such as:

- Credit cards
- Debit cards
- Digital wallets
- UPI
- Net banking
- Cash on Delivery

Third-party payment gateways can be used for online payment processing.

---

## Order Tracking

Users should be able to track order progress:

```text
ORDER PLACED
      ↓
PAYMENT CONFIRMED
      ↓
ORDER PROCESSING
      ↓
PACKED
      ↓
SHIPPED
      ↓
OUT FOR DELIVERY
      ↓
DELIVERED
```

---

## Shipping and Delivery

The system should:

- Store customer delivery addresses.
- Allow users to select delivery methods.
- Determine the nearest suitable warehouse.
- Allocate inventory from the selected warehouse.
- Generate shipments.
- Track delivery progress.
- Provide estimated delivery times.

---

## Promotions and Discounts

Users should be able to:

- Apply promo codes.
- Receive product discounts.
- Receive festival offers.
- Receive loyalty-based discounts.
- Receive cart-level discounts.
- Receive category-level discounts.

The promotion system should validate:

- Expiry
- User eligibility
- Minimum order amount
- Product/category eligibility
- Usage limits

---

## Reviews and Ratings

Users should be able to:

- Review products.
- Rate products.
- Review their shopping experience.
- Rate delivery/service quality.

Reviews should only be submitted for eligible purchases.

---

## Wishlist

Users should be able to:

- Add products to their wishlist.
- Remove products.
- View saved products.
- Move products from wishlist to cart.

# 3. Consistency / Availability

## Consistency > Availability

For Big Bazaar, consistency is more important for financial and inventory operations.

Strong consistency should be used for:

- Payment transactions.
- Order creation.
- Inventory reservation.
- Stock deduction.
- Promo validation.
- Refunds.
- Order totals.

Eventual consistency can be used for:

- Order tracking.
- Shipment location.
- Notifications.
- Search indexes.
- Product recommendations.
- Analytics.
- Reviews.

---

## Why Strong Consistency for Inventory?

Consider:

```text
Available Stock = 1

Customer A ───────► Buy Product
Customer B ───────► Buy Product
```

Without proper consistency:

```text
Customer A → sees 1
Customer B → sees 1

Both purchase

          ↓

Overselling
```

With inventory reservation:

```text
Stock = 1
   │
   ▼
Reserve Stock
   │
   ▼
Stock = 0
   │
   ▼
Other customers cannot purchase
```

# Load Balancer

The load balancer distributes incoming traffic across multiple application instances.

```text
                    Internet
                       │
                       ▼
               Global Load Balancer
                       │
          ┌────────────┼────────────┐
          ▼            ▼            ▼
      Server A      Server B      Server C
          │            │            │
          └────────────┼────────────┘
                       ▼
                    Services
```

This prevents a single application server from becoming a bottleneck.

---

# Data Replication

Use database replication for high availability.

```text
                     Primary DB
                         │
            ┌────────────┼────────────┐
            ▼            ▼            ▼
        Replica 1    Replica 2    Replica 3
```

Read-heavy operations can use replicas while transactional writes go to the primary.

# 8. Scaling of DB

## Horizontal Scaling

Distribute data across multiple database nodes.

```text
                 Database Cluster
                       │
          ┌────────────┼────────────┐
          ▼            ▼            ▼
       Shard A       Shard B       Shard C
```

Possible shard keys:

- Region
- User ID
- Order ID
- Store ID

---

# Regional Partitioning

Partition data by geography.

```text
India
 │
 ├── North
 │
 ├── South
 │
 ├── East
 │
 └── West
```

This can reduce latency and keep regional traffic close to its data.

---

# Order Sharding

Orders can be distributed using:

```text
hash(order_id) % N
```

or through region-based partitioning:

```text
Order
 │
 ├── North Region
 ├── South Region
 ├── East Region
 └── West Region
```

```text

                       │

             ▼         ▼         ▼
         Replica 1  Replica 2  Replica 3
```

Benefits:

- High availability

# Most Important Design Decisions

## 1. Inventory Must Be Strongly Consistent

The biggest e-commerce problem is overselling.

```text
Product Stock = 1
       │
       ▼
Inventory Reservation
       │
       ▼
Stock Reserved
       │
       ▼
Payment
       │
       ├── Success → Deduct Stock
       │
       └── Failure → Release Stock
```

---

## 2. Payment Must Be Idempotent

A network retry should never create two charges.

```text
Payment Request
      │
      ▼
Idempotency Key
      │
      ▼
Payment Service
      │
      ├── New Request
      │      │
      │      ▼
      │    Charge
      │
      └── Duplicate Request
             │
             ▼
       Existing Result
```

---

## 3. Product Browsing Should Be Cache-Heavy

Most users browse products but do not immediately purchase them.

Therefore:

```text
Product Requests
      │
      ▼
Redis Cache
      │
      ├── HIT → Fast Response
      │
      └── MISS → Database
```

This significantly reduces database load during sales.

---

## 4. Warehouse Should Be Part of Inventory Design

Inventory is not globally interchangeable.

```text
Customer
   │
   ▼
Delivery Address
   │
   ▼
Nearest Eligible Warehouse
   │
   ▼
Inventory Check
   │
   ▼
Reserve Stock
   │
   ▼
Ship Order
```

This improves delivery latency and reduces unnecessary inter-warehouse transfers.

---

## 5. Event-Driven Processing

Non-critical operations should not block checkout.

```text
Order Created
     │
     ▼
Kafka
     │
     ├── Notification
     ├── Analytics
     ├── Shipment
     ├── Inventory Events
     └── Order Tracking
```

The user-facing checkout path stays fast while downstream systems process events asynchronously.

## Final Takeaway

The Big Bazaar backend should use a **microservices + event-driven architecture** where the critical shopping path remains strongly consistent while high-volume asynchronous operations are handled through Kafka/RabbitMQ.

The most important systems are:

```text
Product Catalog
      +
Search
      +
Cart
      +
Order
      +
Inventory
      +
Payment
      +
Warehouse
      +
Shipping
      +
Delivery
```

The architecture achieves scalability through **horizontal service scaling, database sharding, replication, caching and asynchronous processing**, while reliability is maintained through **idempotency, retries, circuit breakers, dead-letter queues, graceful degradation and multi-region replication**.

For an e-commerce platform like Big Bazaar, the three most critical guarantees are:

```text
       ┌──────────────────────────────┐
       │       BIG BAZAAR CORE        │
       ├──────────────────────────────┤
       │                              │
       │  1. Never double-charge      │
       │                              │
       │  2. Never oversell stock     │
       │                              │
       │  3. Never lose an order      │
       │                              │
       └──────────────────────────────┘
```

Everything else—recommendations, reviews, wishlist, analytics and promotional features—should be designed so that they can degrade independently without taking down the core **browse → cart → checkout → payment → fulfillment → delivery** journey.
